# 7 - mobile app

Turn the website into an installable app. Decision: keep the React + Vite web app as the single codebase and wrap it with Capacitor. No rewrite.

Goals: stability and ease of testing. Almost all work must be verifiable in a desktop browser (Vite + Playwright) without an emulator or device.

Native capabilities needed eventually: app store integration, notifications, camera, live speech to text. This phase covers only the PWA and the Android shell. Native capabilities come in later phases, behind the interfaces described below.

## Part 1 - PWA basics

- Add a web app manifest (name, short name, theme and background colors, `display: standalone`, start URL) in `frontend/public`.
- Generate icons from `public/pigeon.svg`: 192, 512, maskable 512, and an Apple touch icon. Link them in `index.html`.
- Add a service worker with an app-shell cache so the site loads offline. Prefer `vite-plugin-pwa`. Sounds and fonts in `public` must be cached too.
- Stub API calls must fail gracefully when offline (clear message, no crash).
- Add `theme-color` meta, safe-area insets (`env(safe-area-inset-*)`) and `viewport-fit=cover`, so the layout works on notched phones.

Done when: Lighthouse PWA check passes and the app can be installed from Chrome on desktop and Android.

## Part 2 - Capacitor shell (Android first)

- Install `@capacitor/core`, `@capacitor/cli`, `@capacitor/android` in `frontend`.
- `capacitor.config.ts`: appId, appName, `webDir: 'dist'`.
- Add npm scripts: `cap:sync` (build + `cap sync`), `cap:android` (open Android Studio), `cap:run:android`.
- Commit the generated `android/` folder. Do not hand edit native code unless unavoidable, and document any such edit in this file.
- Set app icon and splash screen from the pigeon asset (`@capacitor/assets`).
- Handle the Android back button (`@capacitor/app`) so it navigates within the app instead of closing it.
- Confirm that audio (`public/sounds`), fonts and the minigame timers work inside the webview.
- Confirm that the deep link / URL parameter flow from phase 6 (friend premium link) works. Needs an intent filter for the site URL.

Done when: the app builds, installs and runs on the Android emulator, with all current features working.

## Part 3 - Native interface layer (preparation only)

Every native feature gets a small TypeScript module in `frontend/src/native/` with one interface and two implementations: the real Capacitor plugin and a web or mock fallback. App code only imports the interface.

Create the folder and interfaces now, with web/mock implementations only. Real plugins are added in later phases.

- `notifications` - request permission, schedule local reminder, cancel. (later: `@capacitor/local-notifications`, `@capacitor/push-notifications`)
- `camera` - take photo, open live stream. (later: `@capacitor/camera`, `getUserMedia`)
- `speech` - start, stop, emit partial and final transcripts. (later: `@capacitor-community/speech-recognition`. Do not use the Web Speech API in the native shell, it is unreliable in iOS webviews.)

Selection happens in one place using `Capacitor.isNativePlatform()`. Mock implementations must be scriptable from tests (for example a fake speech source that emits given text).

## Testing

- Unit tests for the native interface mocks and the selection logic.
- Playwright (desktop browser, mobile viewport) against `vite preview`: existing flows plus install manifest checks.
- Android emulator smoke test is manual for now: launch, play one minigame, open profile, background and resume.
- Real device checks (push delivery, mic and camera permission prompts, store purchases) are the user's job and will be listed per phase.

## Out of scope

- iOS. Needs a Mac or macOS CI runner (GitHub Actions or Codemagic). Planned as its own phase after Android is stable.
- Store listing, signing, and release pipeline.
- Any real native plugin integration (notifications, camera, speech, purchases).

## Implementation notes

Commands (in `frontend`): `npm run icons` (re-render PNGs from `pigeon.svg`), `npm run assets` (Android icon/splash from `frontend/assets`), `npm run cap:sync`, `npm run cap:android`, `npm run cap:run:android`, `npm test` (vitest), `npm run test:e2e` (Playwright, builds and serves `vite preview`; run `npx playwright install chromium` once).

- PWA: `vite-plugin-pwa` generates the manifest and an app-shell service worker. All of `public` (sounds, font, icons) is precached.
- Offline: the stub API throws `ApiError('offline')` when `navigator.onLine` is false; login, create account and invite pages show the message.
- Safe area: `viewport-fit=cover` and `.safe-area` padding on `Container`.
- Native layer: `frontend/src/native/` (`notifications`, `camera`, `speech`, each an interface + `Mock*` + `Web*`). Selection only in `native/index.ts` (`createNative`, `setNative` for tests). Until real plugins exist the shell uses the web fallbacks.
- Back button and deep links: `native/appEvents.ts`. Nested `PagesStack`s register one back handler each, the innermost wins; at the root page the app minimizes. Links arrive as `appUrlOpen`/launch URL and feed the same gift flow as the page URL.
- Gift links built inside the shell use `SITE_URL` (`VITE_SITE_URL`, default `https://wrongway.io`) because the webview origin is `https://localhost`.
- Hand edit in native code: `android/app/src/main/AndroidManifest.xml` has an extra `intent-filter` (VIEW, https, host `wrongway.io`) for the gift link. `autoVerify` needs `https://wrongway.io/.well-known/assetlinks.json` served with the app signing fingerprint, otherwise Android shows a chooser. Change the host here if the domain changes.
- Placeholders to confirm (see open questions): `appId` `io.wrongway.app`, site domain `wrongway.io`.
